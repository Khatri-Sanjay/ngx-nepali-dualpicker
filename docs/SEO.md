# Search metadata and indexing

## Production sites

- Documentation is prerendered with a title, description, canonical URL and social image for every documented route. Its homepage uses WebSite structured data; guide pages use TechArticle and BreadcrumbList data. Source-package identity and version come from the library manifest.
- Playground has a prerendered homepage with its own canonical URL, description, social image and WebApplication data. Hydration enables the interactive controls. `/playground` redirects to the canonical root on Vercel.
- Each production site has a robots.txt and sitemap.xml. Documentation sitemaps contain the documented pages; the playground sitemap contains its root. Missing documentation pages are noindex and have no canonical or stale social URL/image metadata.
- npm discovery metadata is maintained in `libs/ngx-nepali-dualpicker/package.json`: package name, description, keywords, homepage, repository and issue tracker.

## Domains and previews

Set `NDP_DOCS_URL`, `NDP_PLAYGROUND_URL` and `NDP_DEPLOY_APP` in each Vercel project as described in [deployment setup](VERCEL-DEPLOYMENT.md). The build supplies these origins to shared configuration. Playground metadata is generated by `scripts/generate-playground-seo.mjs`; documentation metadata is rendered from its route catalog and site configuration.

Vercel production builds allow indexing. Preview builds emit noindex metadata, disallow crawling, omit canonical identity and add a noindex response header. Do not override `VERCEL_ENV`. No preview domains are added to a production sitemap.

The logo, favicon and social card are described in [brand assets](BRANDING.md). Indexing policy changes require redeployment; crawler and sharing-preview caches update on their own schedules.

## Verify

```sh
npm run build
npm run check:docs-site
npm run check:seo
```

`check:seo` checks the actual prerendered output for both sites, including content, canonical/indexing policy, structured data, sharing cards, robots, sitemaps and assets. Run it after matching production builds of both sites. For preview output, use the corresponding `VERCEL_ENV` value. `check:vercel` additionally checks the selected app's local Vercel routing/output artifact.

Browser tests verify metadata changes and 404 cleanup. After changing playground rendering, also check the deployed page for hydration errors and verify real date selection.
